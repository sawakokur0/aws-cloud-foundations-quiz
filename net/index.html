Lecture 1

Networking Today. Basic Switch and End Device Configuration

Из чего состоит сеть, какие бывают сети и подключения к интернету, четыре свойства надёжной сети, тренды, а затем Cisco IOS: доступ, режимы, синтаксис команд, базовая настройка и сохранение конфигурации.

Компоненты сети

Host / end device
Любой компьютер в сети. Сообщение начинается и заканчивается на end device (ПК, ноутбук, телефон, принтер, IP-телефон, сервер).
Server
Компьютер, который предоставляет информацию: email server, web server, file server. На нём стоит серверное ПО.
Client
Компьютер, который отправляет запросы серверу: браузер запрашивает страницу у web server, почтовый клиент забирает письма с email server.
Intermediary device
Соединяет end devices: switch, wireless access point, router, firewall. Также управляет потоком данных: regenerate and retransmit сигналы, хранит информацию о существующих путях, сообщает другим устройствам об ошибках и сбоях связи.
Network media
Среда передачи: медные провода (электрические импульсы), оптоволокно из стекла или пластика (импульсы света), беспроводная передача (модуляция определённых частот электромагнитных волн).

Peer-to-Peer

Устройство может быть одновременно клиентом и сервером. Рекомендуется только для очень маленьких сетей.

Плюсы

  • Easy to set up
  • Less complex
  • Lower cost
  • Для простых задач: передача файлов, общий принтер

Минусы

  • No centralized administration
  • Not as secure
  • Not scalable
  • Slower performance

Представления и топологии

  • NIC (Network Interface Card) — подключает устройство к сети. Physical port — разъём на устройстве. Interface — специализированный порт; термины port и interface часто используются как синонимы.
  • Physical topology diagram — физическое расположение промежуточных устройств и прокладка кабелей (комнаты, стойки).
  • Logical topology diagram — устройства, порты и схема адресации (IP-адреса, сети).

Типы сетей

По размеру: small home (несколько компьютеров + интернет), SOHO (Small Office / Home Office: домашний или удалённый офис подключается к корпоративной сети), medium to large (много площадок, сотни и тысячи компьютеров), world wide (интернет, сотни миллионов компьютеров).

  • Intranet — частная сеть LAN/WAN организации, доступна только её членам и тем, у кого есть разрешение.

Подключение к интернету

Дом и малый офис

  • Cable — высокая пропускная способность, always-on, от кабельного ТВ-провайдера.
  • DSL — высокая пропускная способность, always-on, по телефонной линии.
  • Cellular — через сеть мобильной связи.
  • Satellite — главный плюс для сельской местности без ISP.
  • Dial-up — дешёвый, низкая скорость, через модем и телефонную линию.

Бизнес

  • Нужны higher bandwidth, dedicated connections, managed services.
  • Dedicated leased line — зарезервированные каналы в сети провайдера между удалёнными офисами.
  • Ethernet WAN (Metro Ethernet) — LAN-технология, расширенная на WAN.
  • Business DSL, в том числе SDSL (Symmetric DSL).
  • Satellite — когда проводного решения нет.
Converged networkРаньше телефон, видео и данные шли по отдельным сетям с разными правилами. Converged network несёт data, voice и video по одной инфраструктуре с одним набором правил и стандартов.

Надёжная сеть: 4 характеристики архитектуры

Fault Tolerance
Ограничивает влияние сбоя (затронуто как можно меньше устройств). Нужны несколько путей (redundancy). Обеспечивается packet switching: трафик режется на пакеты, каждый может пойти своим путём. В circuit-switched сетях (выделенный канал) так нельзя.
Scalability
Сеть можно быстро и легко расширить для новых пользователей и приложений без ухудшения для существующих. Достигается следованием принятым стандартам и протоколам.
Quality of Service (QoS)
Главный механизм надёжной доставки для всех пользователей. Голос и живое видео требовательны; рывки видео = спрос на bandwidth выше доступного и QoS не настроен. С QoS-политикой роутер управляет потоком данных и голоса.
Security
Network infrastructure security (физическая защита устройств, запрет неавторизованного доступа) и information security (защита передаваемых данных). Три цели: Confidentiality (читают только адресаты), Integrity (данные не изменены в пути), Availability (своевременный надёжный доступ для авторизованных).

Тренды

  • BYOD (Bring Your Own Device) — «any device, with any ownership, used anywhere»: ноутбуки, планшеты, смартфоны, e-readers.
  • Online collaboration — Cisco WebEx / Webex Teams: сообщения, картинки, видео, ссылки.
  • Video communications — видеозвонки и конференции (Cisco TelePresence).
  • Cloud computing — хранить файлы и запускать приложения на серверах в интернете; возможно благодаря data centers. Четыре типа облаков: Public (для всех, pay-per-use или бесплатно), Private (для одной организации, например правительства), Hybrid (два и более типа, части связаны одной архитектурой), Custom (под отрасль: здравоохранение, медиа; может быть private или public).
  • Smart home — техника в бытовых приборах (духовка знает из календаря, когда ты придёшь).
  • Powerline networking — подключение к LAN через электророзетку адаптером, данные на определённых частотах; удобно там, где не достаёт Wi-Fi.
  • Wireless broadband — WISP (Wireless ISP, чаще в сельской местности) и сотовая технология с антенной снаружи дома.

Cisco IOS: доступ

  • Shell — интерфейс пользователя (CLI или GUI). Kernel — связывает железо и ПО, распределяет ресурсы. Hardware — физическая часть.
  • GUI удобнее, но может падать и зависать, поэтому сетевые устройства обычно настраивают через CLI.
Console
Физический management port. Для обслуживания и начальной настройки (устройству не нужна сеть).
SSH
Secure Shell: защищённое удалённое CLI-подключение через виртуальный интерфейс по сети. Рекомендуемый способ удалённого доступа.
Telnet
Незащищённое удалённое подключение: логин, пароли и команды идут plaintext.

Terminal emulation programs для подключения через console, SSH или Telnet: PuTTY, Tera Term, SecureCRT.

Базовая настройка

Hostname

Первая команда на любом устройстве. По умолчанию имя заводское (у коммутатора Cisco это «Switch»). Правила: начинается с буквы, без пробелов, заканчивается буквой или цифрой, только буквы, цифры и дефисы, меньше 64 символов. Вернуть по умолчанию: no hostname.

Пароли

Длиннее 8 символов, смесь регистров, цифр и спецсимволов, не один пароль на все устройства, не обычные слова. В лабах используют cisco и class — это слабые пароли, не для продакшена.

Switch(config)# hostname Sw-Floor-1
Sw-Floor-1(config)# line console 0          ! пароль user EXEC через консоль
Sw-Floor-1(config-line)# password cisco
Sw-Floor-1(config-line)# login             ! без login пароль не спрашивается
Sw-Floor-1(config-line)# exit
Sw-Floor-1(config)# enable secret class     ! пароль privileged EXEC
Sw-Floor-1(config)# line vty 0 15           ! удалённый доступ Telnet/SSH, 16 линий
Sw-Floor-1(config-line)# password cisco
Sw-Floor-1(config-line)# login
Sw-Floor-1(config-line)# exit
Sw-Floor-1(config)# service password-encryption   ! шифрует все plaintext-пароли
Sw-Floor-1(config)# banner motd # Authorized Access Only! #
Sw-Floor-1(config)# end
Sw-Floor-1# copy running-config startup-config
  • VTY lines — виртуальные линии для Telnet/SSH. Многие коммутаторы Cisco поддерживают 16 линий: 0 15.
  • startup-config и running-config показывают большинство паролей открытым текстом → service password-encryption, проверить через show running-config.
  • Banner MOTD предупреждает неавторизованных; # — delimiting character, ставится до и после текста.

Lecture 2

Protocols and Models

Правила коммуникации, функции протоколов, наборы протоколов и TCP/IP, организации стандартов, модели OSI и TCP/IP, сегментация, PDU, инкапсуляция и деинкапсуляция.

Правила коммуникации

Мало иметь соединение: устройства должны договориться, как общаться. Три элемента любой коммуникации: source (отправитель), destination (получатель), channel / media (путь). Все коммуникации регулируются протоколами — правилами.

Протоколы учитывают

  • Identified sender and receiver
  • Common language and grammar
  • Speed and timing of delivery
  • Confirmation / acknowledgment

Требования сетевых протоколов

  • Message encoding
  • Message formatting and encapsulation
  • Message size
  • Message timing
  • Message delivery options
Encoding
Преобразование информации в форму, пригодную для передачи. Decoding — обратный процесс.
Formatting & encapsulation
Сообщение должно иметь определённый формат, который зависит от типа сообщения и канала.
Message size
Кадры ограничены по размеру (минимум и максимум), поэтому длинное сообщение режется на части, у каждой своя адресация; у получателя части собираются обратно.
Message timing
Flow control — скорость и объём передачи. Response timeout — сколько ждать ответа. Access method — когда можно отправлять; collision = два устройства передают одновременно. Есть проактивные протоколы (предотвращают коллизии) и реактивные (восстанавливаются после).
Delivery optionКому
Unicastone to one
Multicastone to many (группа, обычно не все)
Broadcastone to all. Есть в IPv4, нет в IPv6. В IPv6 добавляется anycast.

Протоколы

Реализуются в software, hardware или в обоих; у каждого своя function, format, rules.

Типы

  • Network communications — общение устройств через сети
  • Network security — аутентификация, целостность, шифрование
  • Routing — роутеры обмениваются маршрутами и выбирают лучший путь
  • Service discovery — автоматическое обнаружение устройств и сервисов

Функции

  • Addressing — кто отправитель и получатель
  • Reliability — гарантированная доставка
  • Flow control — эффективная скорость
  • Sequencing — уникальная метка каждого сегмента
  • Error detection — испорчены ли данные
  • Application interface — process-to-process между приложениями

Protocol suites

Protocol suite — группа взаимосвязанных протоколов для одной коммуникационной функции. Рассматриваются по уровням: верхние и нижние (нижние перемещают данные и обслуживают верхние).

  • TCP/IP — самый распространённый, поддерживается IETF. Open standard (свободно доступен любому производителю) и standards-based (одобрен организацией стандартов для interoperability).
  • OSI — разработан ISO и ITU.
  • AppleTalk (Apple) и Novell NetWare (Novell) — проприетарные.

Протоколы TCP/IP работают на application, transport и internet уровнях. Самые частые LAN-протоколы network access уровня: Ethernet и WLAN.

Сегментация и инкапсуляция

  • Segmenting — разбиение сообщения на меньшие части. Multiplexing — чередование нескольких потоков сегментов в одном канале.
  • Плюсы сегментации: increases speed (большие данные не занимают канал целиком) и increases efficiency (повторно отправляются только потерянные сегменты, а не весь поток).
  • Sequencing — нумерация сегментов для сборки у получателя; за это отвечает TCP.
  • Encapsulation — каждый протокол добавляет свою информацию (header, у кадра ещё trailer). На каждом этапе у PDU (Protocol Data Unit) своё имя.
  1. DataApplication (data stream)
  2. SegmentTransport (+ TCP/UDP header)
  3. PacketNetwork (+ IP header)
  4. FrameData link (+ header и trailer)
  5. BitsPhysical (bit stream)

Encapsulation — процесс сверху вниз: уровень делает своё и передаёт ниже, пока данные не уйдут битами. De-encapsulation у получателя — снизу вверх: каждый уровень снимает свой заголовок и передаёт выше: bits → frame → packet → segment → data. Пример: web server инкапсулирует страницу, клиент деинкапсулирует её для браузера.

Physical Layer

Зачем нужен физический уровень, его стандарты (components, encoding, signaling), bandwidth и родственные термины, медь (UTP, STP, coax), straight-through и crossover, оптоволокно, беспроводная среда и Wi-Fi: каналы, частоты, RSSI и SNR.

Назначение

  • До любой коммуникации нужно физическое подключение к локальной сети, проводное или беспроводное. Подключает устройство NIC; у устройства может быть несколько NIC (wired и wireless). Не все подключения одинаково быстры.
  • Физический уровень транспортирует биты через среду. Принимает от data link уровня целый кадр и кодирует его в серию сигналов. Это последний шаг инкапсуляции.
  • Следующее устройство на пути принимает биты, снова собирает кадр и решает, что с ним делать.
  • На домашнем беспроводном роутере: антенны Wi-Fi, несколько Ethernet switchports и internet port.

Стандарты физического уровня

Их пишут организации по железу и электрике: ISO, EIA/TIA, ITU-T, ANSI, IEEE (а не IETF, как для верхних уровней). Три функциональные области:

Physical components
Железо, среда и разъёмы, которые передают сигналы: NIC, интерфейсы, коннекторы, материалы и конструкция кабелей.
Encoding
Превращает поток битов в формат, который распознает следующее устройство: предсказуемые шаблоны. Примеры: Manchester, 4B/5B, 8B/10B. В Manchester бит кодируется переходом в середине интервала (по Cisco: 0 = переход high→low, 1 = low→high).
Signaling
Как «1» и «0» представлены в среде: электрические сигналы по меди, импульсы света по оптике, микроволновые сигналы по беспроводной среде.

Straight-through или crossover

Straight-through

Оба конца по одному стандарту (T568A–T568A или T568B–T568B). Соединяет разные устройства:

  • switch ↔ router
  • switch ↔ PC
  • switch ↔ server

Crossover

Один конец T568A, другой T568B (пары передачи и приёма меняются местами). Соединяет однотипные:

  • switch ↔ switch
  • router ↔ router
  • router ↔ PC (оба «хосты»)
  • PC ↔ PC
ПравилоSwitch с «хостами» (PC, server, router) → straight-through. Одинаковые группы (switch–switch, а также router и PC между собой) → crossover. Сейчас многие устройства умеют auto-MDIX и подстраиваются сами.

  • Реже UTP из-за цены, но передаёт дальше и быстрее любой другой среды.
  • Меньше затухание и полностью невосприимчив к EMI/RFI.

Назначение data link уровня

Свойства IP, заголовки IPv4 и IPv6, как хост решает local / remote и использует default gateway, таблица маршрутизации роутера, MAC и IP вместе, ARP, начальная настройка роутера, интерфейсов и default gateway.

Сетевой уровень

Даёт конечным устройствам обмениваться данными. Основные протоколы: IPv4 и IPv6. Четыре операции: addressing end devices, encapsulation, routing, de-encapsulation.

  • IP инкапсулирует сегмент транспортного уровня; IPv4 или IPv6 не влияет на сегмент L4.
  • Пакет просматривают все L3-устройства на пути. IP-адресация не меняется от источника до получателя (кроме NAT).
Connectionless
Не устанавливает соединение перед отправкой, нет управляющей информации (синхронизации, подтверждения). Если нужно соединение, это делает другой протокол, обычно TCP.
Best effort
Не гарантирует доставку: нет механизма повторной отправки (меньше overhead), не ждёт подтверждений, не знает, работает ли получатель.
Media independent
Не важно, какой кадр на L2 и какая среда на L1: медь, оптика, беспроводная.

IP ненадёжен (unreliable): не исправляет потерянные или испорченные пакеты, не переотправляет, не упорядочивает. Это делают другие протоколы.

  • MTU (Maximum Transmission Unit) сетевой уровень узнаёт из управляющей информации data link уровня.
  • Fragmentation: L3 режет пакет IPv4 на меньшие части, например роутер переходит из Ethernet в медленный WAN с меньшим MTU. Фрагментация добавляет latency. IPv6 роутеры не фрагментируют.

IPv6

Ограничения IPv4: address depletion (адреса кончились), нет end-to-end connectivity (частные адреса и NAT), рост сложности (NAT задумывался временным, добавляет latency и мешает troubleshooting).

IPv6 разработан IETF: 128-битные адреса, упрощённый заголовок (меньше полей), не нужен NAT.

  • Заголовок упрощён, но не меньше: фиксирован 40 байт.
  • Убраны поля IPv4: Flags, Fragment Offset, Header Checksum (и IHL, Identification, Options).

Как маршрутизирует хост

  • Пакет всегда создаётся у источника; каждый хост строит свою таблицу маршрутизации.
  • Хост отправляет: себе (loopback 127.0.0.1, ::1), локальным хостам (та же LAN), удалённым хостам (другая сеть).
  • Local или remote: IPv4 — по своему IP, маске подсети и IP получателя; IPv6 — по префиксу, который анонсирует локальный роутер.
  • Локальный трафик выходит с интерфейса хоста к промежуточному устройству (коммутатору). Удалённый трафик идёт на default gateway.
Default gatewayРоутер или L3-коммутатор. IP в том же диапазоне, что LAN; принимает данные из LAN и может отправить их за её пределы; умеет маршрутизировать. Нет шлюза или он неверный → трафик не выйдет из LAN, а внутри LAN всё работает. Хост узнаёт шлюз статически или по DHCP (IPv4), в IPv6 через Router Solicitation (RS) или вручную. Шлюз — это маршрут «последней надежды» в таблице хоста.

Таблица маршрутизации на Windows: route print или netstat -r. Три секции: Interface List (интерфейсы и MAC), IPv4 Route Table, IPv6 Route Table.

MAC и IP вместе

  • MAC (L2, physical) — от NIC к NIC в одной сети. IP (L3, logical) — от источника до конечного получателя.
  • Получатель в той же сети → destination MAC = MAC самого получателя.
  • Получатель в удалённой сети → destination MAC = MAC default gateway, а destination IP остаётся IP конечного хоста.
  • Связь IPv4 ↔ MAC находит ARP, IPv6 ↔ MAC — ICMPv6 (Neighbor Discovery).

ARP

Две функции: resolve IPv4 → MAC и вести ARP table (кэш соответствий IPv4–MAC).

  1. Чтобы отправить кадр, устройство ищет в ARP table IPv4 и MAC.
  2. Получатель в той же сети → ищет IPv4 получателя. В другой сети → ищет IPv4 default gateway.
  3. Нашёл → берёт MAC как destination MAC кадра.
  4. Не нашёл → отправляет ARP request (broadcast FF-FF-FF-FF-FF-FF: «у кого этот IP?»). Владелец отвечает ARP reply (unicast) со своим MAC, запись попадает в таблицу.

Default gateway

  • На хосте: шлюз используется, когда пакет идёт в другую сеть; это обычно адрес интерфейса роутера в локальной сети хоста. PC1 адресует пакет на IPv4 PC3, но отправляет кадр на G0/0/0 роутера R1. IP хоста и интерфейса роутера должны быть в одной сети.
  • На коммутаторе: нужен, чтобы управлять коммутатором удалённо из другой сети. Команда в global config: ip default-gateway 192.168.10.1. Коммутатор L2 трафик хостов не маршрутизирует, шлюз нужен только для его собственного management-трафика.

L1 · Networking Today компоненты, сети, надёжность

  • Сервер предоставляет, клиент запрашивает; в P2P устройство и то и другое: просто и дёшево, но нет централизации, безопасности и масштабируемости.
  • Media: медь — электрические импульсы, оптика — свет, беспроводная — модуляция частот электромагнитных волн.
  • LAN: маленькая область, одна организация, быстро. WAN: большая область, провайдеры, медленнее.
  • Интернетом никто не владеет; за структурой следят IETF, ICANN, IAB.
  • Дом: cable (ТВ-кабель), DSL (телефонная линия), cellular, satellite (сельская местность), dial-up. Бизнес: leased line, Metro Ethernet, business DSL / SDSL, satellite.
  • Converged network: данные, голос и видео по одной сети и одним правилам.
  • 4 свойства архитектуры: fault tolerance (несколько путей, packet switching), scalability, QoS, security (CIA: confidentiality, integrity, availability).
  • Облака: public, private, hybrid, custom. Тренды: BYOD, collaboration, video, cloud, smart home, powerline, wireless broadband (WISP).

L2 · Protocols and Models правила, наборы, модели

  • 3 элемента коммуникации: source, destination, channel.
  • Требования к протоколам: encoding, formatting / encapsulation, size, timing (flow control, response timeout, access method), delivery options.
  • Unicast — одному, multicast — группе, broadcast — всем (нет в IPv6, там anycast).
  • Функции протоколов: addressing, reliability, flow control, sequencing, error detection, application interface.
  • HTTP — веб, TCP — разговоры и гарантия доставки, IP — глобальная доставка, Ethernet — от NIC к NIC в одной LAN.
  • TCP/IP — open standard, IETF. OSI — ISO и ITU. AppleTalk, Novell NetWare — проприетарные.
  • IEEE — Ethernet и Wi-Fi; EIA — проводка и стойки; TIA — радио, VoIP; ITU-T — видео, IPTV, DSL; ICANN / IANA — адреса и домены.
  • Сегментация повышает скорость и эффективность (переотправляются только потерянные сегменты); sequencing делает TCP.

L3 · Physical Layer среда и сигналы

  • Physical layer принимает кадр от data link и отправляет его сигналами; последний шаг инкапсуляции.
  • Стандарты: physical components, encoding, signaling. Их пишут ISO, EIA/TIA, ITU-T, ANSI, IEEE.
  • Медь: дёшево, но attenuation, EMI/RFI, crosstalk. UTP гасит помехи cancellation (скрутка пар с противоположной полярностью).
  • Coax: антенны и кабельный интернет. TIA/EIA-568 — стандарт кабельной разводки; Cat 3, 5/5e, 6 — категории.
  • Fiber полностью невосприимчив к EMI/RFI и электрическим опасностям; дорогой; backbone, FTTH, long-haul, submarine. Разъёмы ST, SC, LC.
  • Wireless: coverage, interference, security, shared medium (half-duplex). WLAN = AP + wireless NIC. BSA, DS, ESS, SSID, BSSID.
  • Wi-Fi 802.11, Bluetooth 802.15, WiMAX 802.16, Zigbee 802.15.4 (IoT).
  • Frequency — как часто (Hz), wavelength — длина цикла, amplitude — сила; free path loss — сигнал слабеет с расстоянием.

L4 · Data Link & Ethernet Switching кадры и MAC

  • Data link: связь NIC–NIC, инкапсулирует пакеты L3 в кадры L2, обнаруживает ошибки (FCS) и отбрасывает испорченные кадры.
  • Кадр = header + data + trailer. Поля: start/stop, addressing, type, control, data, error detection.
  • L2-адрес используется только для локальной доставки и переписывается на каждом хопе.
  • WAN-топологии: point-to-point, hub and spoke, mesh. LAN: star / extended star; legacy bus и ring.
  • Contention-based: CSMA/CD и CSMA/CA. Controlled: Token Ring, ARCNET.
  • NIC принимает кадр, если dst MAC = свой, broadcast или multicast своей группы; иначе отбрасывает.
  • Коммутатор: learn по source, forward по destination; неизвестный unicast, broadcast и multicast → flood во все порты кроме входящего.

L5 · Network Layer, ARP, Router Config IP и маршрутизация

  • 4 операции сетевого уровня: addressing, encapsulation, routing, de-encapsulation.
  • IP: connectionless, best effort (не гарантирует доставку), media independent; ненадёжность компенсирует TCP.
  • Фрагментация IPv4 на роутере при меньшем MTU даёт latency; IPv6 роутеры не фрагментируют.
  • IPv4: Version, DS, Header Checksum, TTL, Protocol, src/dst 32 бита. IPv6 убрал Flags, Fragment Offset, Header Checksum; добавил Flow Label.
  • IPv4 проблемы: исчерпание адресов, нет end-to-end (NAT), сложность. IPv6: 128 бит, проще заголовок, без NAT.
  • Хост решает local / remote по своему IP и маске; remote → на default gateway (MAC шлюза в кадре, IP получателя в пакете).
  • Маршруты роутера: directly connected (автоматически), remote (static или dynamic), default.
  • ARP: ищет в ARP table IP получателя (local) или IP шлюза (remote); нет записи → ARP request broadcast, ответ unicast.
  • Коммутатору нужен ip default-gateway, только чтобы им управляли из другой сети.
