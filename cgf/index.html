Image formation

В компьютерной графике мы формируем (обычно 2D) изображения процессом, похожим на физические системы: cameras, microscopes, telescopes, human visual system.

Elements of image formationObjects · Viewer · Light source(s) · Attributes (как свет взаимодействует с материалом). Важна независимость объектов, наблюдателя и источников света.

Свет и цвет

Light = часть электромагнитного спектра, на которую реагирует зрение: примерно 350–750 nm. Длинные волны выглядят красными, короткие синими (violet 388–440, blue 440–490, green 490–565, yellow 565–590, orange 590–630, red 630–780 nm). Спектр описывается spectral energy distribution: белый (все волны), серый (меньше энергии), лазер (одна волна).

Luminance image

Монохромное: значения = уровни серого, как ч/б плёнка или ТВ.

Color image

Перцептивные атрибуты: hue, saturation, lightness. Совпадать по каждой частоте спектра не нужно.

Three-color theory

В глазу два типа сенсоров: rods (монохромные, ночное зрение) и cones (цветовые, три типа). В мозг идут только три числа, tristimulus values, поэтому достаточно совпасть по трём значениям, то есть хватает трёх primary colors.

Ray tracing и synthetic camera

Ray tracing: прослеживаем лучи от источника и смотрим, какие попадают в линзу. Но каждый луч может много раз взаимодействовать с объектами. Global vs local lighting: цвет объекта нельзя посчитать независимо, потому что объекты загораживают свет, отражают его друг на друга и бывают полупрозрачными.

Synthetic camera model: от точки p идёт projector к center of projection; пересечение с image plane = проекция p. Геометрия проецируется на плоскость, точка закрашивается по локальной информации (local lighting).

Pinhole cameraТочка (x, y, z), плёнка на расстоянии d: xp = −x/(z/d), yp = −y/(z/d), zp = d. Это уравнения simple perspective (подобные треугольники).

Почему local lighting удобно

  • объекты, наблюдатель и свет разделены;
  • 2D-графика — частный случай 3D;
  • простой API: задаём objects, lights, camera, attributes, а изображение строит реализация;
  • быстрая аппаратная реализация, pipelined и parallel вычисления.

Why not ray tracing?

Для простых объектов (полигоны, quadrics) и точечных источников он несложен и даёт глобальные эффекты (тени, многократные отражения), но медленный и плохо подходит для интерактивных приложений. Железо для ray tracing (Pixel Machines) не выжило на рынке; на современных GPU ray tracing близок к real time.

Models and Architectures

API должен задать только objects, materials, viewer, lights. Как его реализовать?

Physical approaches

Ray tracing: следим за лучами от COP, пока они не поглотятся или не уйдут в бесконечность. Глобальные эффекты есть, но медленно и нужна вся база объектов сразу. Radiosity: подход через перенос энергии, очень медленный.

Practical approach

Обрабатываем объекты по одному в порядке генерации приложением, только local lighting. Pipeline architecture: все шаги в железе на видеокарте.

Graphics pipeline

  1. Vertex processingobject → camera → screen coords; каждая смена координат = матрица; цвета вершин
  2. Clipping & primitive assemblyвершины собираются в отрезки, полигоны; всё вне view volume отсекается
  3. Rasterizationдля каждого объекта набор fragments; атрибуты вершин интерполируются
  4. Fragment processingцвет пикселя (texture или интерполяция), hidden-surface removal
Projection
Объединяет 3D-вид с 3D-объектами в 2D-изображение. Perspective: все projectors сходятся в center of projection (как фото). Parallel: projectors параллельны, вместо COP — direction of projection; хорошо передаёт форму и размеры.
Fragment
«Potential pixel»: позиция в frame buffer + color и depth. Может быть закрыт более близким фрагментом.
Clipping
Виртуальная камера, как настоящая, видит только часть мира; объекты вне объёма clipped out.

API

  • Objects: ограниченный набор primitives — points (0D), line segments (1D), polygons (2D), некоторые curves и surfaces (quadrics, parametric polynomials). Всё задаётся через vertices.
  • Camera: 6 degrees of freedom (позиция центра линзы + ориентация), lens, film size, ориентация film plane.
  • Lights: point vs distributed, spot lights, near/far, цвет. Materials: absorption (цвет), scattering (diffuse, specular).
  • Также ввод с устройств (мышь, клавиатура) и возможности системы.

Week 1 · Lecture 1.2

Programming with OpenGL: Background & Complete Programs

Immediate vs retained mode, история API до OpenGL, версии OpenGL, библиотеки (GLUT, GLEW), OpenGL как state machine, формат функций, структура программы, VAO и buffer objects, системы координат.

Immediate vs Retained mode

Immediate

  • геометрия рисуется, когда CPU отправляет её на GPU
  • всё надо слать заново, даже если ничего не изменилось
  • после отрисовки на GPU удаляется
  • большой bandwidth CPU↔GPU, мало памяти GPU

Retained

  • геометрия отправляется на GPU и хранится
  • показывается по команде CPU
  • CPU может слать только трансформации
  • мало передач, но GPU нужно много памяти

История API

  1. IFIPS 1973два комитета: GKS (2D, ISO/ANSI в 80-х) и Core (2D+3D)
  2. PHIGSиз CAD, database model, retained graphics (structures)
  3. X WindowDEC/MIT, client–server; PEX = PHIGS+X, неудобный
  4. SGI GL 1982pipeline в железе, 3D-интерактив стал простым
  5. OpenGL 1992platform-independent, близко к железу, только rendering

OpenGL не включает windowing и input, чтобы не зависеть от оконной системы. Изначально immediate mode, позже добавил retained. Управлялся ARB (SGI, Microsoft, Nvidia, HP, 3DLabs, IBM…), теперь Khronos Group. До версии 2.5 стабилен и backward compatible; новые возможности железа (3D textures, vertex и fragment programs) приходили через extensions.

Modern OpenGL

Производительность за счёт GPU, которым управляют программы-shaders. Работа приложения — отправить данные на GPU; рендерит GPU.

OpenGL 3.1 (2009)Полностью shader-based: нет default shaders, каждое приложение даёт vertex и fragment shader. Нет immediate mode, мало state variables, большинство функций 2.5 deprecated (помечены устаревшими, чтобы постепенно убрать). Backward compatibility не обязательна.
OpenGL ES
Для embedded systems. 1.0 ≈ упрощённый 2.1; 2.0 ≈ упрощённый 3.1 (shader based); 3.0 ≈ упрощённый 4.3.
WebGL
JavaScript-реализация ES 2.0 в браузерах.
OpenGL 4.1–4.5
Добавили geometry и compute shaders и tessellator.
DirectX
Только Windows. Плюсы: лучше контроль ресурсов, высокоуровневые функции. Минусы: новые версии не backward compatible, только Windows. Шейдеры сближают его с OpenGL.

OpenGL как state machine

Группы функций: primitives (points, line segments, triangles), attributes, data transfer & control (color, transformation, lighting), control и input (GLUT), query. Два типа функций:

Primitive generating

Могут дать вывод, если примитив виден. Как обрабатываются вершины и как выглядит примитив, определяет state.

State changing

Transformation и attribute функции. В 3.1 большинство state variables задаёт приложение и шлёт в шейдеры.

OpenGL не объектно-ориентированный, поэтому у одной логической функции много версий: glUniform3f, glUniform2i, glUniform3dv.

Формат имениglUniform3fv(p): gl — библиотека GL, Uniform — имя, 3 — размерность, f — float, v — p указатель на массив. Константы в gl.h/glu.h/glut.h: GL_DEPTH_TEST, GL_COLOR_BUFFER_BIT; типы GLfloat, GLdouble.

Shader-based OpenGL — скорее data flow, чем state machine: действие происходит в шейдерах. GLSL — C-подобный язык с vector/matrix типами, перегрузкой операторов, C++-конструкторами (как Cg и HLSL); шейдеры передаются как исходный код и компилируются.

Структура программы

  • main() — задаёт callbacks, открывает окна, входит в event loop (последний оператор).
  • init() — state variables (viewing, attributes), VAO, buffers, clear color.
  • initShader() — read, compile, link shaders.
  • callbacks — display, input, window functions.
int main(int argc, char** argv){
  glutInit(&argc, argv);                        // init + command line
  glutInitDisplayMode(GLUT_SINGLE | GLUT_RGB);  // window properties (ORed)
  glutInitWindowSize(500, 500);                 // pixels
  glutInitWindowPosition(0, 0);                 // from top-left of display
  glutCreateWindow("simple");
  glutDisplayFunc(mydisplay);                   // display callback
  glewInit();

  glutMainLoop();                               // infinite event loop
}
void mydisplay(){
  glClear(GL_COLOR_BUFFER_BIT);
  glDrawArrays(GL_TRIANGLES, 0, 3);
  glFlush();
}

Старый «простой» код с glBegin(GL_QUAD)…glEnd() больше не работает: функции deprecated и он опирался на default-значения состояния (viewing, colors, window), которых больше нет. Но processing loop тот же. Display callback обязателен в каждой GLUT-программе и вызывается, когда окно надо обновить (например, при открытии).

VAO и Buffer Objects

У вершины много атрибутов: position, color, texture coordinates, application data.

VAO
Vertex Array Object объединяет все данные вершин. glGenVertexArrays(1,&a); glBindVertexArray(a); Bind позволяет переключаться между массивами.
Buffer object
Переносит много данных на GPU. Create → bind → data.
GLuint buffer;
glGenBuffers(1, &buffer);                       // create ids
glBindBuffer(GL_ARRAY_BUFFER, buffer);          // make current
glBufferData(GL_ARRAY_BUFFER, sizeof(points), points, GL_STATIC_DRAW);
  • glBindBuffer(target, id): GL_ARRAY_BUFFER — атрибуты вершин; GL_ELEMENT_ARRAY_BUFFER — массив индексов для glDrawElements. Первый вызов создаёт буфер нулевого размера.
  • glBufferData(target, size, data, usage): size в байтах; usage = подсказка производительности.
  • glBufferSubData(target, offset, size, data) — заменяет часть данных; общий размер должен быть задан glBufferData заранее.
  • glDeleteBuffers(n, ids) — удалить, содержимое теряется.

Координаты, камера, viewport

  • Object (world, model, problem) coordinates — единицы задаёт приложение → camera (eye) coordinates → window coordinates (пиксели).
  • Камера OpenGL в начале координат смотрит в −z. Default view volume — куб со стороной 2 с центром в начале: (−1,−1,−1) → (1,1,1).
  • Default orthographic проекция: точки проецируются вдоль z на плоскость z = 0.
  • glViewport(x, y, w, h) — часть окна под изображение, в пикселях.
  • Проекция делается projection matrix. Старые функции трансформаций deprecated; варианты: свой код, GLSL-функции или vec.h/mat.h.

Math Preliminaries, Shaders, Color & Attributes

Векторы, dot и cross product, матрицы; vertex и fragment shaders, GLSL (типы, qualifiers, функции, swizzling); примитивы OpenGL, triangulation, атрибуты и цвет.

Геометрия: что нужно знать

  • Affine geometry: scalars, points, vectors и операции над ними. Нет углов и расстояний. Affine combination α₁v₁ + … + αₙvₙ при Σα = 1.
  • Euclidean geometry добавляет inner (dot) product: длина, расстояние, нормализация, угол, ортогональность, ортогональная проекция.
  • Projective geometry — для перспективы.

Vector = n-ка чисел; сложение (коммутативно, ассоциативно, есть 0) и умножение на скаляр. Vectors ≠ points: точки складывать нельзя, но можно найти вектор между двумя точками.

Dot productu·v = u₁v₁ + … + uₙvₙ = |u||v| cos θдлина |v| = √(v·v), нормализация v/|v|, ортогональность u·v = 0, проекция
Cross productA×B = (aybz − azby, azbx − axbz, axby − aybx)вектор, ортогональный A и B (не параллельным) → нормаль
Matricesсложение, identity (1 на диагонали), умножение — не коммутативно; индекс с 0 или 1 — как договоришься
Determinant, transpose, inversedet [a b; c d] = ad − bc (рекурсивно для больших); transpose меняет строки и столбцы; AB = BA = I → B = A⁻¹ (только квадратные)

Shaders

Vertex shader

Раз на вершину. Moving vertices: transformations (modeling, projection), morphing, wave motion, fractals, particle systems. Lighting: более реалистичные модели, cartoon shaders.

Fragment shader

Раз на фрагмент. Per-fragment lighting (Phong shading, а per-vertex — Gouraud), texture mapping, procedural textures, environment mapping, bump mapping.

GLSL

  • Типы: int, float, bool, uint, double; vec2/3/4 (ivec, bvec, uvec, dvec); mat2/3/4 — хранятся по столбцам, обращение m[row][column]; samplers. Конструкторы: vec3 a = vec3(1.0, 2.0, 3.0); vec2 b = vec2(a);

Примитивы и полигоны

GL_POINTS, GL_LINES, GL_LINE_STRIP, GL_LINE_LOOP, GL_TRIANGLES, GL_TRIANGLE_STRIP, GL_TRIANGLE_FAN.

OpenGL рисует только треугольникиПолигон корректно рисуется, если он simple (рёбра не пересекаются), convex (отрезок между любыми двумя точками внутри) и flat (все вершины в одной плоскости). Проверка дорогая, поэтому приложение делает tessellation / triangulation (в OpenGL 4.1 есть tessellator).
  • Длинные тонкие треугольники рисуются плохо, равносторонние хорошо → maximize minimum angle; для неструктурированных точек — Delaunay triangulation.
  • Convex polygon: abc, убрать b, потом acd… Concave: рекурсивное деление.

Attributes и цвет

  • Attributes: color, size и width (points, lines), stipple pattern, polygon mode (filled, edges, vertices). Функцией OpenGL осталось мало (glPointSize).
  • RGB: каждая компонента отдельно в frame buffer, обычно 8 бит; 0.0–1.0 (float) или 0–255 (unsigned byte).
  • Smooth shading (default) — интерполяция цветов вершин; flat — цвет первой вершины, делается в шейдере.
  • Цвет окончательно задаётся в fragment shader, но может прийти из приложения (uniform или vertex attribute), из vertex shader (varying) или вычисляться в fragment shader.

Geometry & Representation

Scalars, vectors, points и coordinate-free геометрия; affine space, прямые, convexity, плоскости, нормали, barycentric coordinates; базис, frames, homogeneous coordinates и смена системы координат.

Coordinate-free geometry

В школе геометрия декартова: точка p = (x, y, z), результаты через алгебру координат. Но это нефизично: точки существуют независимо от произвольной системы координат, и большинство результатов от неё не зависит (два треугольника равны, если равны две стороны и угол между ними). Нужен минимальный набор элементов: scalars, vectors, points.

Scalars
Элементы множества с двумя операциями (сложение, умножение) и аксиомами (ассоциативность, коммутативность, обратные). Real, complex numbers. Геометрических свойств нет.
Vectors
Величина с direction и magnitude: сила, скорость, directed line segment. Есть обратный (−v), умножение на скаляр, zero vector (нулевая длина, направление не определено), сумма head-to-tail. Vectors lack position: одинаковые длина и направление = один и тот же вектор.
Points
Положение в пространстве. v = P − Q (точка − точка = вектор), P = v + Q (точка + вектор = точка). Точки складывать нельзя.
Linear vector space
Scalar–vector multiplication и vector–vector addition: v = u + 2w − 3r. Для геометрии мало — нет точек.
Affine space
Точки + векторное пространство: vector+vector, scalar·vector, point+vector, scalar ops. Определяем 1·P = P, 0·P = 0 (zero vector).

Lines, rays, segments

Parametric formP(α) = P₀ + α d — все точки через P₀ в направлении d. α ≥ 0 — ray. Через две точки: P(α) = Q + α(R − Q) = αR + (1 − α)Q, при 0 ≤ α ≤ 1 — отрезок QR.

Формы прямой в 2D: explicit y = mx + h, implicit ax + by + c = 0, parametric x(α) = αx₀ + (1−α)x₁. Параметрическая форма устойчивее и общее, обобщается на curves (P(α), нелинейная функция) и surfaces (P(α, β)); линейные функции дают плоскости и полигоны.

Convexity, affine sums, convex hull

  • Convex: для любых двух точек объекта весь отрезок между ними в объекте.
  • Affine sum: P = α₁P₁ + … + αₙPₙ имеет смысл при α₁ + … + αₙ = 1.
  • Если ещё все αᵢ ≥ 0 — convex hull: наименьший выпуклый объект, содержащий точки («shrink wrapping»).

Planes, triangles, normals

Плоскость задаётся точкой и двумя векторами или тремя точками: P(α, β) = R + α(Q − R) + β(P − R) = R + αu + βv.

Triangle: convex sum точек → при 0 ≤ α, β ≤ 1 получаем все точки треугольника.

Barycentric coordinatesТреугольник выпуклый, поэтому любая точка внутри — affine sum: P(α₁, α₂, α₃) = α₁P + α₂Q + α₃R, α₁ + α₂ + α₃ = 1, αᵢ ≥ 0.

Normal: у каждой плоскости есть вектор n, перпендикулярный ей. Из формы R + αu + βv: n = u × v, эквивалентная форма плоскости (P(α, β) − P₀) · n = 0.

Linear independence, dimension, basis

  • v₁…vₙ linearly independent, если α₁v₁ + … + αₙvₙ = 0 только при всех α = 0: ни один нельзя выразить через другие.
  • Dimension = максимальное число линейно независимых векторов.
  • В n-мерном пространстве любые n независимых векторов — basis; любой v = α₁v₁ + … + αₙvₙ, коэффициенты единственны.
  • Список {α₁…αₙ} = representation вектора в этом базисе: v = 2v₁ + 3v₂ − 4v₃ → a = [2, 3, −4]ᵀ. В OpenGL сначала object basis, потом нужна запись в camera (eye) basis.

Чтобы связать объекты с миром, нужна frame of reference: «где точка?» без неё не ответить (world coordinates, camera coordinates).

Frames

Coordinate system (только базис) недостаточна для точек: векторы не имеют положения, так что два одинаковых вектора в разных местах — «оба правильные». В affine space добавляем к базису одну точку, origin P₀, и получаем frame (P₀, v₁, v₂, v₃):

  • вектор: v = α₁v₁ + α₂v₂ + α₃v₃;
  • точка: P = P₀ + β₁v₁ + β₂v₂ + β₃v₃.

Проблема: записи p = [β₁ β₂ β₃] и v = [α₁ α₂ α₃] выглядят одинаково — точку легко спутать с вектором.

Homogeneous coordinates

Single representationОпределив 0·P = 0 и 1·P = P: v = [α₁ α₂ α₃ 0][v₁ v₂ v₃ P₀]ᵀ, P = [β₁ β₂ β₃ 1][v₁ v₂ v₃ P₀]ᵀ. Значит вектор = [α₁ α₂ α₃ 0]ᵀ, точка = [β₁ β₂ β₃ 1]ᵀ.
  • Общая форма точки [x y z]: p = [wx wy wz w]ᵀ; обратно (w ≠ 0): x ← x′/w, y ← y′/w, z ← z′/w.
  • w = 0 → вектор; для точки обычно w = 1: [x y z 1].
  • Точка 3D заменяется прямой через начало координат в 4D.

Почему это ключ ко всей графике

  • все стандартные трансформации (rotation, translation, scaling) — умножение на матрицы 4×4;
  • hardware pipeline работает с 4-мерными представлениями;
  • для orthographic viewing держим w = 0 для векторов и w = 1 для точек;
  • для перспективы нужна perspective division.

Change of coordinate systems

Один вектор в двух базисах: v = α₁v₁ + α₂v₂ + α₃v₃ = β₁u₁ + β₂u₂ + β₃u₃. Каждый uᵢ выражается через {v}: uᵢ = γᵢ₁v₁ + γᵢ₂v₂ + γᵢ₃v₃. Коэффициенты дают матрицу M 3×3, и a = Mᵀb.

Change of frames (P₀, v₁, v₂, v₃) → (Q₀, u₁, u₂, u₃): дополнительно Q₀ = γ₄₁v₁ + γ₄₂v₂ + γ₄₃v₃ + P₀ → матрица 4×4. Для точек и векторов в обоих frames a = Mᵀb (4-я компонента 1 у точек, 0 у векторов). M задаёт affine transformation в homogeneous coordinates.

General и affine transformations

Трансформация переводит точки в точки и/или векторы в векторы: Q = T(P), v = T(u).

Affine transformationLine preserving. Сюда входят rigid body (rotation, translation), scaling, shear. В графике важно, что достаточно преобразовать концы отрезков (вершины), а линию между ними нарисует реализация.

Pipeline: vertices → transformation T (из приложения) → rasterizer → pixels в frame buffer.

Notation: P, Q, R — точки; u, v, w — векторы; α, β, γ — скаляры; p, q, r и u, v, w жирным — их представления (массивы из 4 чисел в homogeneous coordinates).

2D, вокруг начала координат на θ: радиус тот же, угол растёт на θ. Из x = r cos φ, y = r sin φ: x′ = r cos(φ + θ) = x cos θ − y sin θ, y′ = x sin θ + y cos θ.

Вокруг оси z в 3D z не меняется (2D-поворот в плоскостях z = const); вокруг x не меняется x, вокруг y не меняется y.

Inverses

Можно не считать общей формулой, а использовать геометрию:

  • T⁻¹(dx, dy, dz) = T(−dx, −dy, −dz)
  • R⁻¹(θ) = R(−θ); так как cos(−θ) = cos θ, sin(−θ) = −sin θ, то R⁻¹(θ) = Rᵀ(θ) (верно для любой rotation matrix)
  • S⁻¹(sx, sy, sz) = S(1/sx, 1/sy, 1/sz)

Concatenation и порядок

Любую affine transformation строим перемножением R, T, S. Одна матрица применяется к множеству вершин, поэтому стоимость построения M = ABCD мала по сравнению с вычислением Mp для всех p. Сложно — понять, какую трансформацию собрать из описания задачи.

Порядокp′ = ABCp = A(B(Cp)) — правая матрица применяется первой (pre-multiply). Для строк: p′ᵀ = pᵀCᵀBᵀAᵀ (post-multiply). Умножение матриц не коммутативно: M₁M₂ ≠ M₂M₁ (например, отражение относительно y и поворот).
  • Euler angles: поворот вокруг произвольной оси раскладывается: R(θ) = Rz(θz) Ry(θy) Rx(θx). Повороты не коммутируют; в другом порядке нужны другие углы.
  • Rotation about a fixed point pf: перенести pf в начало → повернуть → вернуть: M = T(p_f) R(θ) T(−p_f).
  • Instancing: объект в начале координат, по осям, стандартного размера; instance transformation: Scale → Orient → Locate, т.е. M = T R S.

Трансформации в OpenGL

До 3.1 матрицы были частью состояния: Model-View (GL_MODELVIEW), Projection, Texture, Color; выбор через glMatrixMode. Концептуально была CTM (current transformation matrix) 4×4, применяемая ко всем вершинам: p′ = Cp; она = model-view × projection.

Операции делали post-multiplication: C ← I, C ← CT, C ← CR, C ← CT⁻¹ даёт C = TRT⁻¹ — «задом наперёд». Чтобы получить C = T⁻¹RT, операции задают в обратном порядке. Последняя заданная операция выполняется первой.

Geometry vs topology
Geometry — положения вершин. Topology — как связаны вершины и рёбра (polygon = упорядоченный список вершин, рёбра между соседними и от последней к первой). Topology сохраняется, даже если geometry меняется. Хорошие структуры их разделяют.
Vertex list
Geometry в одном массиве вершин; polygon list хранит указатели (индексы) в него. Filled polygons рисуются правильно, но если рисовать рёбрами, общие рёбра рисуются дважды.
Edge list
Каждое ребро — пара индексов вершин; общие рёбра хранятся один раз. Полигоны при этом не представлены.

Classical viewing

Три элемента: objects, viewer с projection surface, projectors от объекта к поверхности. Классические виды основаны на их взаимном расположении; наблюдатель сам поворачивает объект, как хочет его видеть. Объекты состоят из плоских principal faces (здания, многогранники, изделия).

Planar geometric projections: проекция на плоскость; projectors либо сходятся в center of projection, либо параллельны. Сохраняют прямые, но не обязательно углы. Для карт нужны nonplanar projections.

Компьютерная графика реализует все проекции одним pipeline; классическое черчение имело отдельную технику для каждой. Главное разделение — parallel vs perspective, хотя математически parallel = предел perspective.

Perspective normalization

Простая перспектива: COP в начале, near plane z = −1, угол обзора 90° (плоскости x = ±z, y = ±z). Матрица с последней строкой [0 0 −1 0]: x′ = x, y′ = y, z′ = z, w′ = −z → x″ = −x/z, y″ = −y/z. Матрица не зависит от far plane.

N =после деления: x″ = −x/z, y″ = −y/z, z″ = −(α + β/z)

Точка проецируется ортогонально в нужное место при любых α и β. Выбираем

α = −(far + near)/(far − near), β = −2·near·far/(far − near)

Тогда near plane → z = −1, far plane → z = 1, стороны → x = ±1, y = ±1: новый clipping volume = default.

Normalization и hidden-surface removalФорма матрицы выбрана так, что если z₁ > z₂ в исходном объёме, то z₁′ > z₂′ после трансформации: порядок по глубине сохраняется, поэтому HSR работает после нормализации. Но z″ = −(α + β/z) искажает расстояния → численные проблемы (depth precision), особенно при маленьком near.

Frustum требует сначала shear (чтобы пирамида стала прямой), затем scale к нормализованному объёму, затем perspective matrix: P = N S H, после чего нужна только ортографическая проекция.

Почему так

  • один pipeline для perspective и orthogonal;
  • 4D homogeneous coordinates как можно дольше, чтобы сохранить 3D-информацию для hidden-surface removal и shading;
  • проще clipping.

Зачем shading

Сфера из многих полигонов одного цвета выглядит плоской. Настоящая сфера выглядит объёмной, потому что из-за взаимодействия света и материала у каждой точки свой оттенок. Нужно учитывать: light sources, material properties, location of viewer, surface orientation.

Scattering и rendering equation

Свет попадает на A: часть рассеивается, часть поглощается; рассеянный попадает на B, снова частично рассеивается, часть возвращается на A, и так далее. Бесконечное рассеяние описывает rendering equation: в общем виде не решается; ray tracing — частный случай для идеально отражающих поверхностей. Она глобальна: тени, многократное рассеяние между объектами, полупрозрачность.

Global

Правильное shading требует расчёта по всем объектам и источникам сразу. Несовместимо с pipeline.

Local

Pipeline закрашивает каждый polygon независимо. В real-time достаточно, чтобы «look right»; глобальные эффекты аппроксимируют отдельными техниками.

Light–material interaction

Свет частично поглощается, частично рассеивается (отражается). Отражённое количество задаёт цвет и яркость: поверхность красная в белом свете, потому что red отражается, остальное поглощается. Характер рассеяния зависит от гладкости и ориентации: гладкая поверхность концентрирует отражённый свет около зеркального направления, шероховатая рассеивает во все стороны.

Источники света

Общие (протяжённые) источники сложны: надо интегрировать свет со всех точек источника. Простые:

Point source
Позиция + цвет. Distant source — бесконечно далеко, лучи параллельны.
Spotlight
Ограниченный точечный источник: direction, cutoff, ослабление ∝ coseφ.
Ambient light
Одинаковое количество света везде; моделирует вклад многих источников и отражающих поверхностей.

Phong model

Простая модель, быстро считается. Три компоненты: diffuse, specular, ambient. Четыре вектора: к источнику l, к наблюдателю v, нормаль n, идеальное отражение r.

Ideal reflectorНормаль определяется локальной ориентацией; угол падения = углу отражения; три вектора компланарны: r = 2(l · n)n − l (все единичные).
Diffuse (Lambertian)
Идеальный рассеиватель: свет рассеивается одинаково во все стороны. Отражение ∝ вертикальной составляющей падающего света: ~cos θᵢ = l · n. Коэффициенты kr, kg, kb — сколько каждой компоненты отражается.
Specular
Большинство поверхностей ни идеально диффузные, ни зеркальные. Гладкие дают specular highlights около направления идеального отражения. Phong: член убывает с ростом угла φ между v и r: I_r ~ ks I cos^α φ. α = shininess: 100–200 — металл, 5–10 — пластик.
Ambient
Результат многократного взаимодействия с окружением; зависит от цвета источников и материала: добавляем ka Ia.
Distance terms
Свет точечного источника ∝ 1/d²; добавляем множитель 1/(a + bd + cd²) к diffuse и specular; константа и линейный член смягчают эффект.
Phong modelДля каждого источника и каждой цветовой компоненты (без distance terms): I = kd Id (l · n) + ks Is (v · r)^α + ka Ia. Вклады всех источников складываются.
  • У каждого источника отдельные diffuse, specular, ambient (без физического обоснования, ради гибкости) × R, G, B → 9 коэффициентов: Idr, Idg, Idb, Isr, Isg, Isb, Iar, Iag, Iab.
  • Материал: 9 absorption coefficients kdr…kab + shininess α.

Too intense: I > 1

  • MIN(I, 1) — объект может менять цвет, уходя в белый: (0.1, 0.4, 0.8) + (0.5, 0.5, 0.5) = (0.6, 0.9, 1.0).
  • Перенормировать все I в 0…1: без пересвета, но надо посчитать все I до рендеринга, картинка может быть слишком яркой, контраст сбит.
  • Image processing по исходным I — лучше, но дорого.

Modified Phong (Blinn) model

Specular-член Phong требует новый reflection vector и view vector для каждой вершины. Blinn предложил аппроксимацию через halfway vector:

Halfway vectorh = (l + v)/|l + v|; заменяем (v · r)^α на (n · h)^β, β подбирают под блеск. Если векторы компланарны, угол ψ между n и h — половина угла между r и v. Это modified Phong / Blinn lighting model, он в стандарте OpenGL.

Нормали

l и v задаёт приложение, r считается из l и n. Проблема — n: способ зависит от представления поверхности. OpenGL оставляет это приложению (кроме deprecated GLU quadrics и Bézier surfaces).

Plane
ax + by + cz + d = 0; по трём точкам: n = (p₂ − p₀) × (p₁ − p₀), нормализовать.
Sphere, implicit
f(x, y, z) = 0 → нормаль = gradient. f(p) = p·p − 1 → n = [∂f/∂x, ∂f/∂y, ∂f/∂z]ᵀ = p.
Parametric
x = cos u sin v, y = cos u cos v, z = sin u. Касательная плоскость задаётся ∂p/∂u и ∂p/∂v → n = ∂p/∂u × ∂p/∂v. Так же для quadrics и parametric polynomial surfaces (Bézier patches).

Shading в OpenGL

Нужны normals, material properties, lights. Старые state-функции (glNormal, glMaterial, glLight) deprecated — считаем в приложении или шлём атрибуты в шейдеры.

  • Normalization: косинусы через dot product; удобнее единичные векторы, но длину меняют трансформации (scaling не сохраняет длину) → в GLSL есть normalize().
  • Point light: позиция + RGBA для diffuse, specular, ambient: vec4 diffuse0 = vec4(1,0,0,1); vec4 light0_pos = vec4(1.0, 2.0, 3.0, 1.0);
  • Позиция в homogeneous coordinates: w = 1 — конечная точка, w = 0 — параллельный источник с заданным направлением. Distance terms обычно квадратичные: 1/(a + b·d + c·d²).
  • Spotlight: direction, cutoff, attenuation ∝ coseφ.
  • Global ambient: ambient зависит от цвета источников (красный свет в белой комнате даёт красный ambient, который исчезает при выключении); глобальный ambient удобен для тестов.
  • Moving lights: источники — геометрические объекты, на них действует model-view. Можно двигать свет вместе с объектами, фиксировать объекты и двигать свет, фиксировать свет и двигать объекты, или двигать всё независимо.
  • Material: соответствует членам модели; w-компонента = opacity (alpha): ambient(0.2,0.2,0.2,1), diffuse(1,0.8,0,1), specular(1,1,1,1), shine = 100.
  • Front and back faces: у каждой грани две стороны; заднюю часто не видно, если важно — обрабатываем в шейдере.
  • Transparency: A в RGBA делает поверхность полупрозрачной, но по умолчанию всё непрозрачно; позже включим blending.

Polygonal shading

Per-vertex shading: расчёт в каждой вершине; цвета вершин становятся shades и идут в vertex shader как атрибут, либо шейдер сам считает по параметрам. По умолчанию shades интерполируются (varying) → smooth shading; uniform даёт один цвет → flat shading.

У треугольника одна нормаль; shades в вершинах почти одинаковые (идентичные для далёкого наблюдателя или без specular). Для сферы хотим разные нормали в вершинах: если центр в начале, n = p — тогда smooth shading работает (но силуэт остаётся многоугольным).

Mesh shading (Gouraud): нормаль вершины = среднее нормалей соседних граней n = (n₁+n₂+n₃+n₄)/|n₁+n₂+n₃+n₄|. Алгоритм (SMF-файл: v… и f…): массив нормалей размера массива вершин → для каждой грани unit normal и прибавить к её вершинам → нормализовать все.

Шейдеры освещения

Per-vertex (Gouraud)

vec3 pos = (ModelView*vec4(vPosition,1)).xyz;
vec3 L = normalize(LightPosition - pos);
vec3 E = normalize(-pos);
vec3 H = normalize(L + E);
vec3 N = normalize(ModelView*vec4(vNormal,0)).xyz;
float d = max(dot(L,N), 0.0);
float s = pow(max(dot(N,H),0.0), Shininess);
vec3 spec = s*SpecularProduct;
if(dot(L,N) < 0.0) spec = vec3(0.0);
color = AmbientProduct + d*DiffuseProduct + spec;
gl_Position = Projection*ModelView*vPosition;
// fragment: frag_color = vec4(color, 1.0);

Per-fragment (Phong)

// vertex shader: outputs interpolated
fN = vNormal;
fE = EyePosition - vPosition.xyz;
fL = (LightPosition.w != 0.0)
   ? LightPosition.xyz - vPosition.xyz
   : LightPosition.xyz;
// fragment shader
vec3 N = normalize(fN), E = normalize(fE),
     L = normalize(fL), H = normalize(L + E);
// same ambient + diffuse + specular,
// specular = 0 if dot(L,N) < 0
frag_color = vec4(ambient+diffuse+specular, 1.0);

AmbientProduct, DiffuseProduct, SpecularProduct = цвет источника × свойство материала, считаются в приложении и передаются uniform'ами.

L1.1Introduction & Image Formation

  • Elements of image formation: objects, viewer, light sources, material attributes; они независимы.
  • Видимый свет ≈ 350–750 nm; длинные волны красные, короткие синие.
  • Three-color theory: rods (ночь, ч/б) и 3 типа cones → 3 tristimulus values → хватает 3 primaries.
  • RGB additive (мониторы, RGB cube; ТВ — YIQ); CMY subtractive (печать; cyan поглощает red); HSV: hue в градусах (R 0, Y 60, G 120), saturation, brightness.
  • Synthetic camera: projector → COP, пересечение с image plane. Pinhole: xp = −x/(z/d).
  • Ray tracing даёт global effects, но медленный и нужна вся сцена; radiosity ещё медленнее. Practical: pipeline, объекты по одному, local lighting, всё в железе.
  • Pipeline: vertex processing → clipping & primitive assembly → rasterization → fragment processing.
  • Fragment = potential pixel (location, color, depth). Hidden-surface removal во fragment processing.
  • API: objects (points 0D, lines 1D, polygons 2D, curves/surfaces через vertices), viewer, lights, materials. Камера: 6 DOF + lens, film size, film plane.

L3.2Geometry & Representation

  • Coordinate-free: scalars, vectors (direction + magnitude, без положения), points (положение).
  • P − Q = vector, P + v = point; точки не складываются. Affine space = точки + векторы; 1·P = P, 0·P = 0.
  • Parametric line P(α) = P₀ + αd: ray α ≥ 0, segment 0 ≤ α ≤ 1; устойчивее explicit/implicit, обобщается на кривые и поверхности.
  • Convex; affine sum (Σα = 1); convex hull (+ α ≥ 0, «shrink wrap»).
  • Plane R + αu + βv, normal n = u × v; barycentric coordinates треугольника.
  • Linear independence → dimension → basis → representation (единственная).
  • Coordinate system недостаточна для точек → frame = origin + basis.
  • Homogeneous: point w = 1, vector w = 0; все T, R, S — 4×4; perspective division.
  • Change of basis/frame: a = Mᵀb; world → camera через model-view (изначально I).

L4.1Transformations

  • Affine = line preserving: rotation, translation (rigid body), scaling, shear; трансформируем только вершины.
  • Матрицы T, Rx/y/z, S, H в homogeneous coordinates; reflection = отрицательный scale.
  • Inverses: T(−d), R(−θ) = Rᵀ, S(1/s).
  • p′ = ABCp: правая первой; умножение не коммутативно.
  • Fixed point: T(p_f) R(θ) T(−p_f). Instance: scale → orient → locate = TRS.
  • Euler angles R = Rz Ry Rx; arbitrary axis — матрица с c, s, t или Rodrigues.
  • CTM: в коде последняя заданная матрица применяется первой. mat.h: Translate, Rotate, Scale, LookAt, Ortho, Perspective.
  • GLSL column-major → glUniformMatrix4fv(loc, 1, GL_TRUE, m).
  • Euler: сложно интерполировать, gimbal lock → quaternions (p′ = r p r⁻¹) и slerp.

L4.2Building Models & Classical Viewing

  • Right-handed: положительный поворот CCW; left-handed: CW, z в экран.
  • Разделять geometry (позиции) и topology (связи). Vertex list: общий массив вершин + индексы. Edge list: общие рёбра один раз, полигонов нет.
  • Порядок вершин CCW снаружи = outward-facing (right-hand rule).
  • Color cube: 8 вершин, quad = 2 треугольника, 6 граней → 36 вершин; mouse выбирает ось, idle крутит theta, шейдер вращает.
  • Classical viewing: objects, viewer + projection surface, projectors. Planar projections сохраняют прямые, не углы.
  • Taxonomy: parallel (multiview orthographic, axonometric: iso/di/trimetric, oblique) и perspective (1/2/3-point).
  • Multiview: расстояния и углы → для измерений, но скрытые грани. Axonometric: 3 грани, foreshortening, углы не сохраняются. Oblique: передняя грань без искажений.
  • Perspective: vanishing points, diminution (реализм), nonuniform foreshortening.

L5.1Computer Viewing & Projection

  • Три шага: камера = model-view, линза = projection, clipping = view volume.
  • Двигаем мир, а не камеру: Translate(0,0,−d); код = обратное движение камеры. C = TR.
  • LookAt(eye, at, up), up не параллелен взгляду. Другие API: VRP/VPN/VUP, yaw-pitch-roll, azimuth-elevation-twist.
  • Перспектива: матрица с последней строкой [0 0 1/d 0] + perspective division на w.
  • Ortho (box), Frustum (может быть несимметричной), Perspective(fovy, aspect = w/h, near, far).
  • Normalization: любая проекция → ортографическая в default cube. Один pipeline, простое clipping, глубина до конца.
  • Pipeline: model-view → projection → perspective division → clipping → projection.
  • Ortho: P = ST; Oblique = shear + ortho; Frustum: P = NSH.
  • N: z″ = −(α + β/z), near → −1, far → 1; порядок глубины сохраняется, но точность падает при маленьком near.
  • Шейдер: gl_Position = projection * model_view * vPosition.

L5.2Shading

  • Shading зависит от light sources, material, viewer position, surface orientation.
  • Свет поглощается и рассеивается; rendering equation глобальна и в общем не решается; pipeline локальный — «look right».
  • Источники: point, distant (w = 0), spotlight (direction, cutoff, cose), ambient. Затухание 1/(a + bd + cd²).
  • Phong: ambient + diffuse + specular, векторы l, v, n, r; r = 2(l·n)n − l.
  • Diffuse (Lambert) ~ l·n, не зависит от наблюдателя. Specular ~ (v·r)^α: α 100–200 металл, 5–10 пластик.
  • 9 коэффициентов источника + 9 материала + shininess. I > 1 → clamp или renormalize.
  • Blinn: h = (l+v)/|l+v|, (n·h)^β — дешевле, стандарт OpenGL.
  • Нормали: (p₂−p₀)×(p₁−p₀); сфера — gradient, n = p; parametric — ∂p/∂u × ∂p/∂v; mesh — среднее нормалей граней. Нормализовать после scaling.
  • Flat (один цвет), Gouraud (освещение в вершинах, интерполируем цвета), Phong shading (интерполируем нормали, освещение во фрагментах).
  • Lessons A2: idle только при анимации (иначе NULL), glutPostRedisplay в конце callback, геометрию слать один раз, порядок матриц.
